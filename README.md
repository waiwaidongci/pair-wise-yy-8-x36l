# 古法纸浆发酵记录

运行：

```bash
npm start
```

访问 `http://localhost:3039`。数据保存在 `data/paper-pulp-fermentation.json`。

## 业务模块

代码按职责拆分为可复用模块，接口与页面都从同一处读写：

| 模块 | 职责 |
| --- | --- |
| `lib/storage.js` | JSON 数据加载、迁移、原子落盘（临时文件 + rename）与串行写队列 |
| `lib/batches.js` | 批次档案：建档、档案更新、追加备注、提交观察、退缸 |
| `lib/observations.js` | 观察记录：温度/气味/纤维/换水/异常原因规范化与汇总 |
| `lib/status.js` | 状态判定：唯一的状态规则来源 |
| `lib/page.js` | 页面渲染（初始数据由 `listBatches()` 注入） |
| `server.js` | HTTP 路由，只做参数收发，业务全部调用 `lib/` |

## 状态判定规则

每次提交观察记录后，状态由系统自动判定，接口与页面均不能直接改状态：

1. **异常优先**：本次观察存在异味或霉点 → `异常观察`，异常原因保留在批次上（`abnormalReason`、`abnormalAt`），并计入异常次数；
2. **满七天其次**：无异常且发酵满 7 天，且同一浸泡缸内没有未退缸的前序批次 → `可抄纸`；
3. 其余 → `发酵中`。

同缸规则：同一浸泡缸里还有未退缸的前序批次（按建档时间排序）时，后续批次即使满七天也不能进入 `可抄纸`，提交仍会保存观察记录，但接口返回 `409 vat_blocked` 并给出明确的中文冲突提示（点名前序批次、负责人、当前状态），页面弹窗提示。前序批次退缸后，同缸已满七天的后续批次自动重判为 `可抄纸`。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/items` | 批次列表（含 `abnormalCount` 异常次数、`lastObservationAt` 最近观察时间） |
| POST | `/api/items` | 建档，编号重复返回 409 |
| GET | `/api/items/:id` | 批次详情（id 或批次编号均可） |
| PATCH | `/api/items/:id` | 改档案字段；传 `status` 返回 403（状态不可直接改） |
| POST | `/api/items/:id/action` | 提交每日观察并自动判定状态；缸冲突返回 409（观察仍已保存） |
| POST | `/api/items/:id/logs` | 追加备注 |
| POST | `/api/items/:id/retire` | 退缸，并联动重判同缸后续批次 |
| GET | `/api/stats` / `/api/statuses` | 状态统计 / 状态与规则说明 |

## 页面

- 列表卡片显示异常次数与最近观察时间，支持「异常次数 / 最近观察时间 / 建档时间」排序，可按状态筛选、关键词搜索；
- 卡片上「继续记录」会把该批次带入每日观察表单，已有批次可继续追加观察；
- 「退缸」按钮将批次置为已退缸，退缸后不能再记观察。

## 并发安全

所有写操作通过同一串行队列执行，配合临时文件原子替换，前后脚提交的多个批次不会再互相覆盖异常结果。
